# Decision: Supabase, no ORM, Better Auth via pg, OpenAI-compatible AIRA (user-confirmed)

- Decision ID: decision-1793360413165-44f142a7
- Recorded by: cross-agent-mcp-bridge
- Recorded: 2026-10-30T11:40:13.165Z

These user decisions replace the earlier Postgres/Drizzle and Claude-for-AIRA choices.

- **Database:** Supabase (Postgres). Run it locally with the Supabase CLI (`supabase start`). The schema lives as SQL migrations in `supabase/migrations/`.
- **No ORM; Drizzle is dropped.** Server-only repositories in `app/api/(db)/` use `pg` (node-postgres) with parameterised SQL and real transactions. Withdrawal is a single transaction: it updates status, bumps the epoch, deletes the embedding row and writes the audit entry.
- **Auth:** Better Auth 1.7.x connects to Supabase Postgres through a `pg` Pool, using the email OTP and organization plugins. Supabase Auth is not used.
- **Supabase lockdown:** every table has RLS enabled with no anon/authenticated policies, and grants to anon/authenticated are revoked, so the auto REST API exposes nothing. The DB URL and service key are server-only. Authorization lives entirely in our DAL `authorize()`.
- **AIRA:** an OpenAI-compatible API through the `openai` SDK, configured with the env vars `AI_BASE_URL`, `AI_API_KEY` and `AI_MODEL`. Free models are the target (OpenRouter, Groq or Ollama). Only approved shared copies and public content may be sent; private text never goes to the provider.
- **Embeddings:** an `embed()` adapter backed by local @huggingface/transformers v4 (all-MiniLM-L6-v2) or an OpenAI-compatible `/embeddings` endpoint. Vectors are stored as jsonb in Postgres, as decided earlier.
