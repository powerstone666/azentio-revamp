# Decision: Database and vectors: Postgres + JSON vectors in jsonb (user-confirmed)

- Decision ID: decision-1793358697787-daaf1fd1
- Recorded by: cross-agent-mcp-bridge
- Recorded: 2026-10-30T11:11:37.787Z

The user confirmed PostgreSQL for all data. Vector search runs locally as JSON vectors, stored as a `jsonb` column in Postgres.

- Table `shared_copy_embeddings` has the columns shared_copy_id (FK, unique), model, dims, embedding jsonb (number[]) and created_at.
- Only approved and active shared copies are embedded. Never embed private drafts, source versions, attachments or reviewer notes (source.md §09).
- Retrieval works in two steps. SQL first selects the rows that are active, within the viewer's audience and allowed by policy. Cosine similarity is then computed in app code (app/api/(services)/search/), and status is re-checked before AIRA returns citations.
- Withdrawal and suspension delete or deny the embedding row in the same DB transaction as the status change. There is no separate JSON file or external index, which keeps withdrawal within 60 seconds by construction.
- Embeddings come from a local Transformers.js sentence model (e.g. all-MiniLM-L6-v2, 384 dimensions) with no API key. This is pending user confirmation.
- pgvector is the upgrade path if scale grows; the schema stays the same apart from the column type.
- Auth is Better Auth with a real email OTP. `DEMO_MODE` accepts a fixed code for seeded accounts only, and it is off in production.
